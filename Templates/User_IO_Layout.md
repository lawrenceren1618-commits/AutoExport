# 用户端 IO（输入 · 输出 · 汇总存档）

> 确认日：2026-07-27（与云端 `/workspace` 对齐；本地 `User_IO/` 为可见 IO 树）  
> 物理根：`User_IO/`  
> 机器键：`Scripts/settled_knowledge_db.json` → `confirmed_defaults.user_io_layout`

## 设计

| 层 | 角色 |
|----|------|
| **`User_IO/{项目}/`** | 你可见的**输入端 / 输出端 / 汇总存档**（简洁上传与取件） |
| **黑箱（现役处理树）** | `1_Input_Raw/Shipments/`、`2_Processed_AI/`、既有脚本：识别、拆并、填表、对照、Gate |
| **旧成品仓** | `3_Output_Final/` 暂保留；目标逐步由 `User_IO/…/输出端` + `汇总存档` 承接「给人看」的交付 |

**原则**：先任务后简洁；不硬收敛 `01/02/03`；处理细节不暴露在用户端夹内。

## 项目命名

与发货项目一致（可与黑箱同名）：

```text
{订单号}_{店铺代码}_{出货日期YYYYMMDD}_{条数}
```

例：`EF-C26080-C07-11590_C07_20260731_13590`

## 目录结构（强制）

```text
User_IO/{项目}/
  输入端/
    发货计划/                  # 店、产品×箱数、下单日、发货日（订单号系统生成）
    亚马逊外箱贴与追踪截图/    # 外箱贴原包/PDF + 追踪编码截图
    货代入库贴/                # 货代回传入库贴（原始上传）
  输出端/
    订单表/                    # 生成的订单表
    出货表/                    # C04/C07-U 短号
    货代下单表/                # 生成的货代入库贴下单表
    报关单证/                  # 生成的报关套表
    产品标签包/                # 工厂贴标用（源只读复制）
    发货贴标包/                # 外箱贴+入库贴按批 zip
  汇总存档/                    # 本票及后续发货涉及文件的审查向存档
```

云端作业主路径：`/workspace`（前台仅输入/输出；提取与处理在后台波次）。库务：`/ops`（非做单主路径）。

模板空树：`User_IO/_TEMPLATE/`。

## 汇总存档

- **用途**：本票及**后续同订单发货**涉及文件的留存，以备国家/海关审查。  
- **范围**：输入原件快照 + 输出终件 + 协议号/对照报告等必要证据；不塞调试 `_tmp_*`。  
- **与 Gate**：正式「审查向」封存建议在 Gate→Final 明示后执行；pre-Final 可先放工作副本并标明状态。
- **库务索引**：按发货日年/月/日浏览 → `/ops/archives`（仅索引，不建物理三级夹；见 [`Shipment_Archive_Index.md`](Shipment_Archive_Index.md)）。
