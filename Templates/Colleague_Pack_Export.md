# 输出端两包（完整存档 · 工厂贴标包）

> 确认日：2026-07-24  
> 机器入口：`Scripts/13_export_output_packs.py`  
> 处理区仍在 `Shipments/{项目}/`；本目录 **只收复制成品**，不做识别/生成。  
> Gate→Final 业务闸门独立：两包可在 `gate_final=WAIT` 时先出「pre-Final 副本」。

## 原则

| | **工厂（处理区）** | **成品仓库（输出端）** |
|--|-------------------|------------------------|
| 位置 | 当票 `Shipments/{项目}/` | `3_Output_Final/{同一项目名}/` |
| 作用 | 识别、拆分、合并、填表、对照 | **只复制**；禁止再跑生成脚本 |
| 内容 | 可含 `_inbox` / `_staging` / `_recognize` | **仅干净成品**；禁止 README、`_PROMOTED`、inbox/staging/recognize、`*.pre_*` |

**禁止**：把处理路径改到成品仓。  
**允许**：从处理区复制已确认成品；原件仍留 Shipments。

---

## 两包结构（强制）

```text
3_Output_Final/{项目文件夹名}/
  完整存档/                         # 发货资料全量存档
    {腿_渠道}/                      # 如 C26079-A_FC、C26079-B_AWD
      订单表/                       # 若按腿拆分则放腿下；否则见共用
      出货表/
      报关资料表/
      货代入库贴下单表/
      外箱贴/                       # 正式 FBA外箱贴 树（无 inbox/staging）
      货代入库贴/                   # 已确认一仓一 PDF（可自 FBA 仓夹收集）
    共用/                           # 整票共用
      订单表/
      出货表/
      产品标签/                     # 可选
  {批次腿}_{实际发货条数}_{出货日期}_贴标包/   # 一腿一包，例：C26079-A_32260_…、C26079-B_4200_…
    # —— 该腿仅 1 个目的仓（扁平）——
    外箱贴_{仓码}/                  # 例：外箱贴_IUTE
    入库贴_{仓码}/                  # 例：入库贴_IUTE
    # —— 该腿 ≥2 个目的仓 ——
    {仓码}/
      外箱贴/
      入库贴/
```

| 包 | 文件夹命名 | 用途 | 必含 |
|----|------------|------|------|
| **完整存档** | 固定 `完整存档/` | 上传的 + 新生成的发货资料记录 | 订单、出货表、报关、外箱贴、货代下单表、货代入库贴 |
| **工厂贴标包** | **一腿一包**：`{腿号}_{实发条数}_{出货日期}_贴标包` | 工厂贴标备货 | 该腿外箱贴 + 入库贴 |

**贴标包命名细则（不用完整 EF 订单号）**：

| 段 | 规则 |
|----|------|
| 批次/腿号 | 固定用拆单腿号，如 `C26079-A`、`C26079-B`（**一腿一个贴标包**） |
| 实际发货条数 | 该腿 `shipped_strips`（部分发货用该批实发数） |
| 出货日期 | `YYYY.M.D`，取自 `PROJECT.json` 的 `ship_date` / `delivery_date` |

**贴标包内部层级（按该腿目的仓数）**：

| 该腿目的仓数 | 结构 |
|--------------|------|
| **= 1** | 贴标包根下直接 `外箱贴_{仓码}/` + `入库贴_{仓码}/`（禁止再套仓码中间层） |
| **≥ 2** | `{仓码}/外箱贴` + `{仓码}/入库贴`（腿号已在贴标包文件夹名上） |

例（本票）：`C26079-B_4200_2026.7.31_贴标包/外箱贴_IUTE/` + `入库贴_IUTE/`；A 腿五仓仍用 `{仓}/外箱贴`。

## 微信发送包（强制）

微信只能发**压缩包**，不能直接发文件夹。成品仓文件夹结构仍保留；对外发送前必须再走本步。

| 项 | 规则 |
|----|------|
| **合并范围** | **同一订单**、**同一出货批次**（同 `ship_date` / 同次发运）下的各腿 **`{腿}_{条数}_{出货日}_贴标包/` 仅此** |
| **不含** | **`完整存档/` 不进微信 zip**（存档仅留成品仓文件夹 / 本机归档，不经微信发） |
| **合并方式** | 同批各腿贴标包顶层文件夹**并入同一个 zip**（根下保持原文件夹名，不拆散内层） |
| **命名** | `{订单短号}_{箱数}箱_外箱贴入库贴.zip`（例：`C26114_290箱_外箱贴入库贴.zip`） |
| **落盘** | 与文件夹同级：`3_Output_Final/{项目}/` 下；文件夹副本**不删** |
| **禁止** | 按腿各打一个 zip 就当「已可发微信」却漏合其他同批腿；禁止把 `_inbox` / staging / README / 完整存档 打进包 |

例（本票同批 A+B）：

```text
3_Output_Final/{项目}/
  完整存档/                         ← 保留，不进 zip
  C26079-A_32260_2026.7.31_贴标包/
  C26079-B_4200_2026.7.31_贴标包/
  C26114_290箱_外箱贴入库贴.zip   ← 仅含上面两个贴标包
```

体积过大无法单文件发微信时：允许按腿拆成多个 `{腿号}_…_贴标包.zip`；须在 `_pack_manifest.json` 注明拆分原因。优先仍尝试「同批贴标包单包」。

脚本：`Scripts/13_export_output_packs.py --zip`（默认开启；`--no-zip` 仅留文件夹）。

> **补充（多单并批）**：微信 zip 仍仅贴标包；命名用**主单短号**加当批总箱数：`C26114_290箱_外箱贴入库贴.zip`。见 [`Colleague_Pack_Export.md`](Colleague_Pack_Export.md)。

## 与入库贴流水线

入库贴须先经 [`Freight_Inbound_Label_Pipeline.md`](Freight_Inbound_Label_Pipeline.md) 三重验证并写入 `FBA外箱贴/{渠道}/{仓}/`，再复制进两包。

**例外（SEND 承运人，如纽酷）**：亚马逊后台下载的外箱贴 PDF **已含入库贴**，该腿**不要求**单独货代回传入库贴；贴标包可仅含外箱贴，manifest 记 `inbound_skipped_send`（见 `freight_forwarder_profiles.json`）。

**普通货代**（如物易通）：无确认入库贴时，完整存档可缺该项并在 manifest 标注 `missing`；贴标包对应仓的 `入库贴/` 标缺失。

## 与 Gate

- `gate_final=WAIT`：两包可标「pre-Final / 同事用副本」，**不替代** Gate→Final。  
- Gate 通过后：可再核一次或人工升格为正式 Final。
