## 1. 主体与品牌（写订单前先判定）

| 订单号片段 | 法律主体（内部） | 订单页眉显示 | 桌布品牌 | 亚马逊店铺 | FNSKU |
|------------|------------------|--------------|----------|------------|-------|
| **C04** | 畅选贸易有限公司（E-fashion 子公司） | **仅** 易尚 / Xuchang E-fashion…（**不写**「畅选」） | **WIGENIUS** | C04 店铺 | 按 C04 店铺，与 C07 **不可共用** |
| **C07** | 易尚电子商务有限公司 | 易尚 / E-fashion | **Dressmaker** | C07 店铺 | 按 C07 店铺，与 C04 **不可共用** |

### 硬性规则

1. 同一套颜色/尺寸的产品，**C04 与 C07 装箱信息可以相同**，但 **品牌、FNSKU（产品标签）必须按主体各自一套**。
2. 生成订单时：根据订单号中的 `C04` / `C07` 自动带入品牌；页眉公司统一用 E-fashion 英文抬头，C04 **不要**在页眉印「畅选贸易有限公司」。
3. 出库/装箱明细中的「产品标签」= 该主体对应店铺的 FNSKU，禁止串店。**出货表本身不填 FNSKU**（已确认）。
4. **装箱规格可变**：同产品 + 同品牌 + 同公司，因克重等变化可能导致 **条数/箱、包数/箱、内外箱** 与历史单不一致。**以沉淀库为准**；计划行不得跳过库。冲突或库空须**立即汇报**，由你确认后再写（见 `.cursorrules` §1.1）。默认倾向仅建议 **90G + 下单日期最新**。
5. 订单号用 **EF 长号**；出货表用 **短号**；二者并存、可追溯，不混印。
6. **上半/出货种类** = **尺寸 + 颜色**；同尺寸同颜色下不同条数/包（2/6/10…）**合并为一行**计总条数。出货明细行数 = 订单上半行数（不固定）。下半才按条数/包 + FNSKU 细分。
7. 尺寸写入优先 canonical：`60X102inch` / `60X126inch` / `70X120inch` / `60X84inch` / `90 inch round`（用 `X` 与 `inch`，不用 `*` 或「英寸」）。

## 2.1 号段对照（已确认）

| 单据 | 号码形态 | 例 |
|------|----------|-----|
| 订单表 | `EF-…-C04/C07-…` 长号 | `EF-C26079-C04-36460` |
| 出货短号（表内） | `{店铺}-{YY}{NN}` | `C04-2616` |
| 出货文件名（表外） | `{短号}-U-{年月日}.xlsx` | `C04-2616-U-2026.7.10.xlsx` |

### 短号命名（强制）

| 段 | 规则 |
|----|------|
| 店铺 | `C04` 或 `C07` |
| 年缩写 YY | 2026→`26`，2027→`27`（依出货年） |
| 本年票序 NN | 本年该店铺第几票出货：`01`、`02`…（两位） |
| 合成 | `C04` + `26` + `16` → **`C04-2616`** |

- **U**：表示目的地美国（USA）；出现在**文件名**中，**不**写入表内短号单元格。  
- 映射：`PROJECT.json` 记录 `order_code` ↔ `outbound_short`；禁止把短号印成工厂订单号，禁止把 EF 长号当作出货短号。  
- 序号：以使用者维护的基准递推；当前 2026 基准用后更新（本票 C04 已用 `2616`）。  
- **多单同日并批**（补充）：同 `ship_date` 合并出货表等口径见 [`Multi_Order_Ship_Batch.md`](Multi_Order_Ship_Batch.md)，不改本文件既有单票规则。
