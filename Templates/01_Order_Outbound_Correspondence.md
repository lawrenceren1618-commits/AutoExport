# ① 订单表 / 出库单 — 字段对应关系

> **独立文档**：只对应「工厂订单 + 出库/装箱单」。  
> **禁止**与货代下单表、报关单据混用字段。  
> 模板来源：优先你上传到 `1_Input_Raw/01_Order_Outbound/` 的表格。  
> 若操作无法继续而全局搜索到候选：须你先归类确认为本类后，方可写入/调用/参考（见 `.cursorrules` §0.1）。

状态：框架已建；**列级映射待你上传正式订单/出库模板后填满。**  
终审：生成草稿后须与 `Scripts/settled_knowledge_db.json` 交叉对照通过，方可输出最终订单/出货表（见 `.cursorrules` §1.2）。

## 1. 主体与品牌（写订单前先判定）

| 订单号片段 | 法律主体（内部） | 订单页眉显示 | 桌布品牌 | 亚马逊店铺 | FNSKU |
|------------|------------------|--------------|----------|------------|-------|
| **C04** | 畅选贸易有限公司（E-fashion 子公司） | **仅** 易尚 / Xuchang E-fashion…（**不写**「畅选」） | **WIGENIUS** | C04 店铺 | 按 C04 店铺，与 C07 **不可共用** |
| **C07** | 易尚电子商务有限公司 | 易尚 / E-fashion | **Dressmaker** | C07 店铺 | 按 C07 店铺，与 C04 **不可共用** |

### 硬性规则

1. 同一套颜色/尺寸的产品，**C04 与 C07 装箱信息可以相同**，但 **品牌、FNSKU（产品标签）必须按主体各自一套**。
2. 生成订单时：根据订单号中的 `C04` / `C07` 自动带入品牌；页眉公司统一用 E-fashion 英文抬头，C04 **不要**在页眉印「畅选贸易有限公司」。
3. 出库/装箱明细中的「产品标签」= 该主体对应店铺的 FNSKU，禁止串店。
4. **装箱规格可变**：同产品 + 同品牌 + 同公司，因克重等变化可能导致 **条数/箱、包数/箱** 与历史单不一致。发现冲突须**立即汇报**；默认倾向**下单日期最新**，写入前须使用者确认（见 `.cursorrules` §1.1）。

## 3. 你上传「发货计划」后 → 本类应填字段（仅订单/出库需要的）

| 源字段 | → 工厂订单 | → 出库/装箱 | 备注 |
|--------|------------|-------------|------|
| 订单号含 C04/C07 | 订单编号 | 可写入备注/关联单号 | 据此选品牌与 FNSKU 池 |
| 品牌名 | 商品品牌 | — | C04→WIGENIUS；C07→Dressmaker（若源表为空则按主体补） |
| 公司名 | 一般**不**写入页眉法律名 | — | 页眉固定 E-fashion；畅选仅作内部归属 |
| 颜色 | 颜色 / COLOR | 装箱品名描述中的颜色 | |
| 尺寸 | 尺寸项 / ITEM | 装箱品名描述中的尺寸 | |
| 条数（总） | 数量 / QTY | 总条数 | |
| 克重 | 布料或 WEIGHT 文案 | — | 如 90G/平方米 |
| 箱数 | 箱数 / 总箱数 | 总箱数 | |
| 条数/箱、内外箱尺寸、毛净重、体积 | 有则写入 | 装箱明细必填侧 | 装箱信息两主体可相同 |
| FNSKU / 产品标签 | 标签列（若有） | **产品标签** | 按店铺；待上传标签表或历史单对照 |

**不填入本类**：仓库代码、FBA 货件号、报关单价/总价、贸易国等（属 02/03）。
